# 需求、现状与实施计划（唯一权威）

更新：2026-11-09。当前代码版本：`0.2.1`；目标宿主及本地已核对安装包：DSH `0.2.2-rc.1`。
当前授权：推进 P0 调查与后续开发；继续使用浏览器版 DSH，接受配套桌面辅助程序。不要求切换 DSH 客户端；本机 Web profile 已链接仓库、Windows 辅助程序已安装；未发布。

## 1. 当前有效目标

在权限审批、提问、计划审核或一轮任务结束时，如果用户没有聚焦事件所属会话，提供弹窗和音效提醒，体验参考 Codex。参考的是用户体验，不假定 Codex 的内部实现或各客户端行为。

2026-11-09 用户要求替代早期与之冲突的决定：

- 优先实现 Web 使用场景，基础兼容 Windows 和 Linux；WSL → Windows 桌面单独验证，不能把 WSL 等同于 Linux 桌面支持。
- 无需预先打开或保持一个可见的通知窗口。一次性安装、授权与日常预开窗口是两回事。
- 弹窗和音效独立开关，分别选择触发事件；关闭弹窗不能连带关闭音效，反之亦然。
- 弹窗 UI 与 DSH 一致；正文、选项、输入、会话入口等操作内容保持极简。
- 多种音效，并允许权限审批、提问、任务结束等事件分别选择音效。
- 交互弹窗可以批准/拒绝，处理单选、多选、自定义输入、计划审核，并一键返回对应会话。
- 尽量兼容 CLI/TUI；没有自绘窗口能力时调用系统通知，Windows 为 Windows 通知，Linux 为桌面通知。
- 更远期支持游戏、全屏视频等场景下不弹窗；音效策略单独决定。
- 可以重做有问题的架构，不以保留现有实现为目标。

这些是目标，不代表当前全部实现。用户已确认选择“浏览器 + 桌面辅助程序”。本轮首要场景已收敛为 Arch WSL 内 DSH Web → Windows 桌面。TUI 已有提醒、Windows DSH Desktop 使用较少，本轮不扩展它们；Linux 原生桌面保留后续目标，不要求为当前原型先指定发行版/桌面。

## 2. 行为契约

### 2.1 事件与静默

| 事件 | 目标行为 |
|---|---|
| 权限审批 | 提醒人工处理；只对用户显式选择提交决定 |
| 提问 | 展示完整问题批次；支持选项与自定义回答 |
| 计划审核 | 单独识别，不误当普通完成；批准/拒绝和回会话 |
| 一轮结束 | 提醒并回会话；完成、错误、长度限制、阻塞区分，用户主动中止默认不提醒 |

“聚焦当前会话”指事件所属会话正在用户前台可见且获得焦点的 DSH 主视图中；此时插件弹窗和音效都静默。仅 Web 在线、仅浏览器进程存在、仅标签页可见均不足以判定。多窗口有任一真实前台视图正在看该会话时应静默。正在操作该会话的交互弹窗时不重复提醒或打断输入。

CLI/TUI 前台会话识别能力尚未验证。若拿不到可靠信号，应明确降级并由用户选择策略，不能声称已实现“当前终端会话静默”。

### 2.2 通道独立

- 总开关控制所有通道，且关闭 Web 后宿主仍应遵循设置。
- 弹窗总开关、音效总开关独立；每类事件分别设弹窗、音效开关和音效预设，支持试听、音量及静音。
- “弹窗关闭”同时禁止自绘窗口与系统兜底；不能改换通道绕过关闭。
- “音效关闭”同时禁止自定义音与插件请求的系统通知音。系统适配器需请求静音并验证效果；不能把系统音当作例外。
- 一个事件最多一次声音与一个主要提醒表面。降级不得重复播放声音。
- GUI 不可用时仍可独立播放声音（有音频环境时）；无桌面/无音频输出需报告能力不足。
- 设置应由宿主或统一配置服务持久化，Web/桌面/CLI 共享对应实例配置。旧 localStorage 需显式迁移，不静默丢弃用户偏好。

### 2.3 窗口与交互

- 通知窗口由事件触发，平时无空白常驻窗口；不能把“手动打开并一直保留”作为验收通过条件。
- 出现时默认不抢键盘焦点；用户点击后可输入；多事件合并排队，不为每条事件堆一个置顶窗口。
- 完成提醒仅保留会话标题（有数据时）、消息正文、“关闭”和“打开会话”；不显示系统标题栏、菜单栏、图标、重复标题。跳转为主按钮，关闭为次按钮；两者具备悬停、按下与键盘焦点反馈，Esc 可关闭；窗口高度跟随内容。
- 每次 UI 修改后实际渲染并检查：去掉不影响阅读、判断和操作的内容，不保留仅用于装饰或重复说明的区域。
- 跟随 DSH 主题 token、字体与语言；浅色/深色、缩放、多屏验证。独立程序没有主文档时需要主题快照/默认主题方案。
- 人工提交必须绑定实例、会话、请求标识与有效状态；成功后同步原界面，失败可见且可重试；已过期/已被其他界面回答的请求禁止再提交。
- 关闭提醒不是拒绝或回答。禁止通过默认选择、超时或重连自动批准/回答；DSH 自身倒计时行为由其原机制管理。
- 一键返回必须定位事件所属会话。仅打开站点首页不算完成；页面关闭时要验证重开后的定位。CLI 的终端激活能力单独验证。
- 系统兜底默认仅提醒和返回；不能为了可作答直接接管审批 waterfall。

## 4. 架构选择与原型

### 4.1 方案与取舍

| 方案 | 收益 | 代价/边界 |
|---|---|---|
| A：纯 DSH 插件 + 操作系统通知 | 安装简单；宿主可在无 Web 页面时发通知；适合先证明可靠投递 | 系统控制外观与交互；浏览器自绘窗口不能承诺后台可靠自动打开；无法完整满足目标体验 |
| B：DSH 插件 + 本地桌面辅助程序 | 桌面进程管理按需窗口和音频，可复用卡片外观；用户继续使用 DSH Web | 增加安装、进程、升级、IPC、平台打包；必须验证答案回传、焦点与 WSL 通信 |
| C：复用可扩展的 DSH 桌面客户端 | 若已有所需窗口/通知接口，可减少自建桌面设施 | 是否存在合适接口尚未核实；可能要求用户换客户端，不能擅自替代 Web 优先目标 |

已确认选择 B；C 的已有接口仅作参考，不引入换客户端前提。A 可作为轻量模式/降级路径，但不能把它的限制改写成用户已同意的降级。能力原型选用 MIT Electron 45.2.3，复用 JS/HTML/CSS；Windows 运行时实测约 357 MiB，开发安装同时保留 WSL 下载副本。该体积只用于当前可替换适配器，不绑定事件/回答协议。

桌面应用通常可直接管理窗口，避开网页开窗手势限制；但不会自动解决 DSH 回答接口、多会话焦点、多平台、重复投递与免打扰。仅套桌面壳、未接入原生窗口能力，不能算解决。

### 4.2 推荐的职责边界

```text
DSH 宿主：事件归一化 + 统一配置 + 投递协调/去重
    ↑ Web/CLI（若可获取）：当前会话、焦点、主题、交互可用性
    ↓ 经确认的桌面能力：自绘窗口 + 独立音频
    ↓ 不可用且弹窗启用时：Windows / Linux 系统通知
人工操作 → 验证实例/会话/请求有效性 → DSH 现有受支持应答接口
```

- 宿主拥有一个投递决策，Web presence 只是状态输入；不再“在线就全权交给 Web”。按请求标识去重，多标签页与多个 DSH 实例隔离。
- 通道返回 accepted / rendered / failed 等实际可观测阶段；OS 通知 API 接受不等于用户看到。按错误/超时降级，仍使用同一事件 ID 防重。
- 第一期允许交互桥接仍在线的 Web Pending 对象；必须标明 Web 断开后该路径不可用。无 Web 的独立作答需另证实官方接口，未证实时只提醒并回会话。
- 保留不写 session log、不注册模型工具、不注入 prompt、不监听/抢占审批与提问 waterfall 的约束。如必要能力与之冲突，先提交取舍，不暗改。
- 桌面通信需实例鉴别、连接授权和请求校验；敏感答案不写诊断日志；不得开放未认证的批准接口。协议与传输在原型阶段决定。

P3 应答桥接已实现并通过 Windows 模拟 Pending 的真实按钮链路验证；不等同于真实 DSH 审批/问题已验收。下一项：加载新版 Host、刷新所有 Web 标签，按 verification 第 11–12 节验收通道及真实交互，优先核实审批事件关联、完整问题批次、continued/rpc、并发失效及精准回会话。未满足这些完成条件前不扩大到 P4/P5。TUI、Desktop 客户端扩展和 Linux 原生桌面不作为本轮前置条件。

## 6. 验收与待定问题

逐项可执行验收见 [verification.md](verification.md)，不能以单元测试替代真实桌面投递。

已确认：Arch WSL 的 DSH Web 为本轮重点，接受 Windows 辅助程序；TUI 和 DSH Desktop 本轮不扩展。当前 Web 访问地址未提供，原型从运行中的页面读取，不需要为选型等待固定地址；真实端到端验收需要可用的 DSH 会话。

待验证：关闭所有 Web 页面后能否受支持地定位会话/作答；CLI/TUI 前台身份；Linux Wayland 下非抢焦点弹窗与激活；系统勿扰与静音支持。Headless/SSH 远程桌面转发不是首轮默认承诺；若使用场景包含它们，需补充单独的传输与桌面目标设计。

### 当前实现边界

- 已安装辅助程序时自动启用，DSH_NOTIFY_COMPANION=0 强制回退；四类事件由宿主统一投递，能关联到在线 Web Pending 的请求支持显式桌面作答；系统兜底只提醒。
- 宿主只观察 session/event，不接管 waterfall。审批结束、问题被回答、任务开始/主动中止会使旧提醒失效；桌面请求撤回保留事件 ID 防止乱序后重现旧卡。
- 新客户端不先播放 Web 音效，由宿主认领后统一发声；旧页面投递接口也共享事件认领。设置修改到 profile 成功后显示已保存；断线修改等待同步，不能假装已经持久化。
- DSH connection 的 requestRejection + admit(owner) 保护自有路由；匿名和非 owner 无法读取设置、伪造 presence 或投递。
- Windows 缺辅助程序时退回现有 PowerShell 只读窗口；系统音不承诺与所选合成预设一致，进程启动也不等同窗口已可见。Linux 原生桌面仍未验收。
- 桌面不直接接管 DSH waterfall；经宿主命令交付给现有 Web Pending.answer。无 Web 页面不支持作答；无 callId、同 callId 重复审批或元数据不匹配时保持只读。旧浏览器作答窗与新桌面表面并存的完整仲裁尚未验证，验收时保持旧窗关闭。
- 应答命令不自动重投；已授权执行但确认丢失时锁定该事件并要求回会话核对。成功仅指现有 Pending.answer 已返回，真实宿主落地与原页面同步仍需端到端验收。窗口草稿只在该辅助程序进程内保留。
